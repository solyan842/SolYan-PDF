# V1.5 — Full Page Flatten parity

## Upstream parity

Stirling PDF exposes two flatten behaviors:

1. flatten interactive form fields; and
2. convert every page to a raster image so text is no longer selectable.

SolYan PDF already had the first behavior through qpdf (`--generate-appearances --flatten-annotations=all`). V1.5 adds the missing full-page raster behavior to the same `/flatten` tool instead of creating a duplicate route.

## Modes

### Forms + annotations

- Server-side qpdf.
- Generates appearances and flattens annotations/widgets into page content.
- Keeps original text/vector page content selectable where qpdf can preserve it.
- Best default when the goal is to freeze fields/comments without degrading page rendering.

### Full Page

- Browser-local PDF.js rendering.
- Reuses `rebuildPdfWithRasterizedPages()` from the existing secure-redaction path.
- Replaces every source page with a PNG drawn on a fresh PDF page.
- Makes page text non-selectable and removes interactive form/annotation/link behavior from rasterized pages.
- Adds no npm package, WASM runtime, backend service, or image-processing dependency.

## DPI and resource limits

The browser-local mode offers 96, 150, and 200 DPI. The default is 150 DPI to balance readability, output size, and browser memory.

Hard limits:

- 100 MB input PDF;
- 200 pages;
- 25,000,000 raster pixels per page;
- 80,000,000 raster pixels total.

If the pixel budget is exceeded, the operation fails before building the output and asks the user to lower DPI or split the PDF.

## Fidelity boundary

Full Page Flatten is intentionally destructive:

- text is no longer selectable/searchable as PDF text;
- vectors become raster pixels;
- form fields, annotations, links, and other page interactivity disappear;
- outlines, attachments, AcroForm catalogs, and other document-level structures are not promised to survive the fresh-page rebuild.

The original source PDF is never modified.

## Verification

Frontend CI must type-check/build the new mixed local/server page. The raster rebuild primitive is the same helper already exercised by Auto Redact Text CI for PDF validity and non-recoverable replaced-page content. No workflow-only change is introduced for this feature.
