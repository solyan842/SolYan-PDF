# V1.5 — Unicode-aware Whole Word Auto Redact

## Goal

Close the Auto Redact parity gap for whole-word matching without adding a backend service, WASM runtime, npm dependency, or a second redaction engine.

## Implementation

- Reuses the existing browser-local PDF.js text-layer scanner.
- Reuses the existing secure 150 DPI raster-redaction/rebuild path.
- Adds an opt-in **Whole Word** switch to Literal mode only.
- Keeps Safe Regex semantics separate; Whole Word does not wrap or rewrite regex patterns.
- Defines word characters with Unicode property escapes: Letter (`L`), Number (`N`), Mark (`M`) and underscore.
- Normalizes literal search text to NFC before comparison so visually equivalent precomposed/decomposed Vietnamese text can match.
- Keeps matching inside a single PDF.js text-run. It never joins text across runs or pages.

## Semantics

A literal occurrence is accepted when the side that starts/ends with a Unicode word character is not adjacent to another Unicode word character.

Examples:

- `an` matches `an toàn`.
- `an` does not match inside `banana`.
- Vietnamese letters with diacritics are word characters.
- Combining marks are word characters, avoiding a false boundary inside decomposed accented text.
- Terms beginning or ending with punctuation only require a boundary on the side whose term edge is a word character.

## Compatibility

The default remains substring Literal matching. Existing callers of `findAutoRedactMatches(...)` are source-compatible because `wholeWord` is an optional final parameter after the existing padding argument.

## Security and fidelity boundary

Whole Word changes only match selection. It does not weaken the secure output path: every page with a match is still rasterized and rebuilt without copying that page's original content stream. The existing Auto Redact resource limits and the warning about losing interactive text/vector/form/annotation content on rasterized pages remain unchanged.

## CI

The existing Auto Redact Text CI still compiles `auto-redact.ts`, runs literal matcher regression, verifies secure multi-page rebuild/non-recoverability, checks production wiring/bounds, and builds the frontend. The connected GitHub session cannot modify `.github/workflows/*`, so no workflow-specific whole-word assertion is added through an alternate path.
