# SolYan PDF V1.3 Close-out

Status: **SELF-CONTAINED SCOPE COMPLETE**

This record closes the current V1.3 OSS-first parity pass after the accepted converter work and PR #100. It supplements `docs/V1.3-PARITY-AUDIT.md`; the detailed engine decisions and per-feature evidence remain there.

## Final accepted V1.3 capability

### UTF-8 TXT → PDF

Status: **implemented and regression-gated**.

SolYan extends the existing LibreOffice Office-conversion service rather than adding another renderer or document engine.

Accepted behavior:

- `.txt` is supported through the existing Document/Office → PDF surface;
- input must be valid UTF-8 or UTF-8 with BOM;
- LibreOffice is invoked with the explicit `Text (encoded):UTF8` input filter so conversion does not depend on server locale;
- the existing 100 MB Office upload bound is reused;
- generated output is validated as PDF before being returned;
- the frontend uses the same 100 MB client-side bound;
- the permanent Office Service CI includes a real Vietnamese UTF-8 TXT → PDF → `pdftotext` round-trip and explicit non-UTF-8 rejection.

On the accepted PR #100 head `28615a18c02a2c9313686f3062ddc6c1467a739c`, Office Service CI, Frontend CI, PDF-to-Office Canary, Synthetic V1 Release Gate, Real-World V1 Release Gate and PDF-to-RTF CI all passed before merge. PR #100 was merged into `main` as `9a2cd58707ba954d1f4968188d9771b7797b7abe`.

#### OSS-first decision

The maintained Stirling-PDF generic file/Office conversion path was reviewed as the parity reference. SolYan reuses the already-bundled LibreOffice service and does not add a second text renderer.

HTML/SVG/Markdown → PDF are not silently folded into this TXT path because they introduce broader external-resource, script, URI and filesystem-resolution surfaces and need separate semantics/security decisions.

## V1.3 self-contained scope summary

The accepted V1.3 parity pass now includes the previously regression-gated capabilities recorded in `docs/V1.3-PARITY-AUDIT.md`, including:

- remove digital signatures;
- bounded PDF inspector / Get ALL Info;
- unlock read-only PDF form fields;
- split photographs from scanner-bed scans;
- PDF → HTML;
- PDF → Text;
- PDF → CBZ;
- PDF → Markdown;
- PDF → XML;
- PDF → RTF;
- PDF → CSV;
- UTF-8 TXT → PDF.

These capabilities preferentially reuse engines already shipped by SolYan PDF: qpdf, Poppler, LibreOffice, PP-StructureV3, PDFium/OpenCV, pdf-lib/PDF.js and existing service adapters.

## Deferred by design

The following are **not unfinished implementation work** in the current self-contained scope:

- PDF → EPUB/AZW3: maintained reference implementations rely on Calibre; adding this is a deliberate runtime/dependency expansion;
- PDF → CBR: RAR creation adds tooling/licensing/deployment complexity while CBZ already provides an open archive path;
- inline PDF content-stream image removal (`BI … ID … EI`): robust support requires a real content-stream parser/dependency expansion, while the current Image XObject removal path remains regression-gated;
- multi-party/remote signing, cloud-storage connectors, AI summarization and PDF translation: product/provider/credential decisions remain required.

No additional self-contained core PDF feature should be added merely to increase parity count. Future work must first identify a concrete user-value gap and pass the repository OSS-first/speed gate.
