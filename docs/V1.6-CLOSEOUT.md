# SolYan PDF V1.6 Closeout — Hybrid PDF Translation

Date: 2026-10-16

## Scope closed

V1.6 closes the first provider-backed product lane in SolYan PDF: PDF translation with a Hybrid / local-first architecture.

The validated release scope is deliberately narrow:

- public browser/provider ID: `argos`;
- source language: English;
- target language: Vietnamese;
- free/local provider: Argos Translate;
- layout-preserving task service: separately deployed PDFMathTranslate 1.9.x HTTP backend;
- outputs: translated-only PDF and bilingual PDF;
- cloud providers remain optional operator configuration and are not V1.6 prerequisites.

## Architecture locked

SolYan core remains Apache-2.0 and does not vendor, patch, import or redistribute PDFMathTranslate AGPL source.

The production-shaped route is:

```text
Browser
  -> SolYan FastAPI /pdf/translate
  -> server-side allow-list and argos:openailiked mapping
  -> external PDFMathTranslate Flask/Celery/Redis HTTP task service
  -> PDFMathTranslate openailiked provider
  -> local SolYan Argos OpenAI-compatible bridge
  -> pinned Argos EN -> VI model
  -> mono or bilingual PDF
```

The public response continues to report `argos`; `openailiked` is an operator-side implementation detail.

## Upstream and model pins

- PDFMathTranslate repository: `PDFMathTranslate/PDFMathTranslate`
- audited commit: `d16604dabb5c3f4c6d4daf37197b218b0dbd4df2`
- CLI version at the audited commit: `1.9.12`
- Argos dependency: `argostranslate==1.11.0`
- model: `translate-en_vi-1_9.argosmodel`
- model SHA-256: `86957101aa4099aa9a1a7492e41987d938d3cf0fdaf4fb684c0797a9d567dd16`

The model is downloaded into the external translation runtime and is not committed to SolYan PDF.

## Why direct upstream Argos was rejected

The first-party PDFMathTranslate 1.x `ArgosTranslator` path failed live validation because the audited source contains two runtime defects:

1. it imports `argotranslate.translate` instead of the installed `argostranslate` package;
2. after a runtime compatibility alias bypasses that typo, execution still fails with `name 'argostranslate' is not defined` and retries.

SolYan does not carry a source patch or fork for this AGPL code path. The accepted architecture reuses PDFMathTranslate's existing OpenAI-compatible provider interface and keeps the workaround entirely in a small local SolYan bridge.

## Permanent CI

`.github/workflows/pdf-translation-ci.yml` remains the lightweight permanent gate. It does not download the translation model on every PR. It verifies:

- backend translation contract;
- server-side provider mapping;
- mono/bilingual behavior;
- public/local provider identity;
- browser credential boundary;
- source/service input validation;
- bridge syntax/compileability;
- pinned model hash documentation;
- presence and runtime-isolation wiring of both live diagnostic workflows.

The live model/full-stack workflows are retained as manual diagnostics because they are much heavier than the normal release CI.

## Product and privacy boundaries retained

- Browser users cannot submit arbitrary upstream URLs or provider API keys.
- Cloud API keys remain deployment/operator configuration only.
- `TRANSLATION_LOCAL_SERVICES` is a deployment classification, not packet-level proof of locality.
- Non-loopback Argos bridge binding requires explicit opt-in and must remain on a trusted private service network.
- PDF upload size, language IDs, provider IDs, task IDs and polling time are bounded.
- Upstream error bodies are not reflected directly to the browser.
- Argos quality is the free/local baseline, not a premium linguistic-quality claim.
- Scanned/OCR-heavy PDFs remain dependent on the external translation/layout engine configuration; SolYan does not silently inject OCR into the translation route without measured evidence.

## Deferred beyond V1.6

The following are not blockers for V1.6 and remain separate product choices:

- additional Argos language-pair model packs;
- measured Ollama model recommendations;
- cloud-provider credential onboarding;
- translation-quality benchmark corpus beyond the controlled live fixture;
- automatic OCR routing for scan-heavy translation;
- migration to PDFMathTranslate 2.0 when it exposes a stable service API matching SolYan's provider-independent contract.

## Closeout status

**V1.6 PDF translation implementation is complete for the validated free/local English -> Vietnamese lane.**

Release packaging can proceed independently from optional cloud-provider configuration.
