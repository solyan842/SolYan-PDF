# V1.5 — Advanced PDF Metadata

## Gap

The original SolYan Metadata tool edited six standard Document Information fields only: Title, Author, Subject, Keywords, Creator and Producer. Maintained Stirling-PDF also exposes CreationDate, ModDate, Trapped, arbitrary custom Document Information fields, and a delete-all mode that removes the catalog Metadata/PieceInfo entries in addition to clearing Document Information.

## OSS-first decision

Keep the feature browser-local and reuse the already-shipped `pdf-lib` stack. The thin low-level layer only accesses the PDF Information dictionary and catalog objects that `pdf-lib` already parsed; no qpdf round-trip, backend endpoint, new package or network service is introduced.

## Accepted behavior

Standard fields:

- Title
- Author
- Subject
- Keywords
- Creator
- Producer
- CreationDate
- ModDate
- Trapped (`True`, `False`, `Unknown`, or unset)

Custom Document Information:

- existing non-standard Info keys are enumerated for editing;
- maximum 50 custom fields;
- key length maximum 64 characters;
- custom keys are restricted to ASCII `A-Z`, `a-z`, `0-9`, `.`, `_`, `:`, `-`, starting with an alphanumeric character;
- custom keys may not shadow standard PDF Info names, case-insensitively;
- duplicate custom keys are rejected case-insensitively;
- value length maximum 4096 characters;
- values are stored as `PDFHexString.fromText(...)`, preserving Unicode text.

Empty standard fields remove the corresponding Info key instead of writing a misleading empty value.

## Delete-all behavior

The explicit **Delete all metadata** mode:

- clears every entry from the Document Information dictionary;
- removes catalog `/Metadata` (normally XMP metadata);
- removes catalog `/PieceInfo`;
- does not subsequently write standard/custom values back in the same operation;
- loads with `updateMetadata: false` so `pdf-lib` does not intentionally refresh document metadata during the edit path.

This is deliberately separate from normal metadata editing.

## XMP boundary

Normal edit mode updates Document Information only. It does **not** attempt to parse/rewrite an arbitrary XMP packet or claim that XMP and Info are synchronized. When the user's goal is metadata removal, Delete All removes the catalog XMP entry. Broader active-content/attachment/history cleanup remains the responsibility of SolYan Sanitization.

## Date boundary

Creation/Modification dates are surfaced through browser `datetime-local` inputs. The selected local wall time is converted to a JavaScript `Date` and written through the public `pdf-lib` date setters. Clearing the input removes the corresponding Info key.

## Resource boundary

- input PDF maximum: 100 MB;
- custom metadata maximum: 50 fields;
- custom key maximum: 64 characters;
- custom value maximum: 4096 characters.

## Verification

Frontend CI must compile and production-build the low-level `PDFDict`/`PDFName`/`PDFHexString` integration and UI. Workflow files are not modified in this lane because the connected GitHub session cannot write `.github/workflows/*`.
