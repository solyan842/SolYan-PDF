# SolYan PDF V1.2 — Maintained OSS Parity Audit

Audit date: 2026-10-14

This audit closes the V1.2 **self-contained parity expansion** milestone. The goal is not endpoint-for-endpoint cloning. SolYan PDF uses maintained open-source projects — primarily Stirling-PDF plus the upstream engines already integrated into SolYan — to identify high-value capabilities, then chooses the smallest privacy-first implementation that fits the existing architecture.

## Audit rules

- Prefer existing browser/engine capabilities before adding a new runtime.
- Do not copy AGPL/proprietary/open-core implementation into the Apache-2.0 core.
- Preserve vector/text content when the selected operation can do so; explicitly label raster-only operations when it cannot.
- A visually hidden or covered value is **not** called securely redacted unless the underlying content is actually removed and regression-tested.
- Provider-dependent features remain separate product decisions rather than being disguised as self-contained work.

## Deliberately not claimed as parity

### Secure automatic redaction

**Not implemented in V1.2.** The basic Editor can draw an opaque rectangle over visible content. That is a visual mask only: underlying text or objects can remain in the PDF. V1.2 therefore does not call this secure redaction or auto-redaction.

A future secure-redaction implementation must prove, with extraction/object-level regression tests, that selected content is actually removed and cannot be recovered by ordinary PDF inspection. Until that gate exists, SolYan must not market the visual mask as data removal.

### Remove certificate/signature structures

**Deferred.** Removing signature fields or certification structures is intentionally not treated as a generic cleanup operation. It changes document-authenticity semantics and needs its own product wording, tamper expectations and validation gate.

### Additional export formats

Dedicated PDF → XML/HTML/CSV and HTML/URL/ebook/Markdown → PDF surfaces are **not V1.2 parity targets**. Some adjacent data is already available through OCR/text/Markdown or Office conversion paths, but SolYan does not claim dedicated endpoint equivalence. They remain future conversion-roadmap candidates if user demand justifies the extra rendering/conversion surface.

### Provider-dependent features

The following remain outside self-contained V1.2 by prior product decision:

- multi-party remote signing;
- cloud-storage provider connectors;
- AI summarization provider;
- PDF translation provider.

## V1.2 closure

The maintained-OSS audit found no further **high-value, self-contained** PDF utility that should block V1.2 after Auto Rotate, Auto Split QR, Decompress, Auto Rename, Stamp and explicit rasterized Color Transform were added. Remaining gaps either already have a functional SolYan equivalent, require security semantics that must not be faked, belong to a broader conversion roadmap, or require an external provider/product decision.

V1.2 can therefore be versioned and released without claiming universal feature parity with any other product.
