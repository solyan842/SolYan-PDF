# SolYan PDF V1.2 — Maintained OSS Parity Audit

Status: **feature-complete for the current self-contained scope**

This document records the V1.2 research and implementation decisions required by `AGENTS.md` so future work does not repeat the same OSS comparison or create duplicate tools.

## Reference and architecture rule

The primary feature-parity reference for this pass was maintained Stirling-PDF behavior, supplemented by the capabilities already present in qpdf, Poppler, PDF.js/pdfjs-dist, pdf-lib, Tesseract, PDFium/pypdfium2 and OpenCV. Stirling-PDF source was used as a behavior/reference audit, not copied into SolYan PDF.

The implementation preference was:

1. reuse an engine already shipped in SolYan PDF;
2. keep browser-local work in PDF.js/pdf-lib where it is bounded and appropriate;
3. use thin qpdf/Poppler adapters for structural PDF operations;
4. use OCR-service PDFium/Tesseract/OpenCV analysis only when page raster analysis is necessary;
5. avoid adding a Java/PDFBox runtime solely to match one utility;
6. keep lossy/rasterized behavior explicit instead of presenting it as lossless PDF editing.

## Added or expanded in V1.2

| Capability | SolYan implementation | Important boundary |
|---|---|---|
| Overlay PDFs | Browser-local PDF.js/pdf-lib compatible page overlay | Rewrites pages and can invalidate signatures |
| One long page | Browser-local vector/text-preserving composition | Bounded by the PDF compatibility page-height ceiling |
| Advanced split | Exact pages-per-part plus best-effort target-size ZIP | Target-size mode is an estimate, not an exact byte guarantee |
| Attachments | qpdf list/add/extract/remove | Rewrites invalidate signatures |
| PDF permissions | qpdf AES-256 permission controls | Security semantics follow qpdf/PDF viewer support |
| Sanitization | qpdf JSON structural removal | Not antivirus or universal exploit detection |
| Remove comments/annotations | qpdf JSON, form-safe by default | Widgets/AcroForm preserved in safe mode |
| Bookmark editor | Browser-local outline read/write | Named/unusual destinations have documented parser limits |
| Split by bookmarks | Browser-local chapter planning + page copy | Child PDFs do not guarantee original interactive/catalog structures |
| Poster PDF | Browser-local printable tiling | Rebuilds visible page content; interactive controls are not preserved |
| Split sections | Browser-local grid extraction | Rebuilds pieces; interactive controls are not preserved |
| Active-content inspector | qpdf JSON reachable-object inspection | Structural-only; never executes JavaScript; not a safety certificate |
| Remove images | qpdf JSON resource rewrite | Removes reachable Image XObjects; inline `BI … ID … EI` images remain out of scope |
| Auto Rotate | Tesseract OSD + PDFium analysis, qpdf relative rotation | Default confidence 14.0; unresolved/low-confidence pages are unchanged |
| Auto Split QR | PDFium/OpenCV QR detection + qpdf page selection | Exact marker only; analysis rasters are temporary |
| Decompress PDF | qpdf `--stream-data=uncompress --object-streams=disable` | Inspection/debugging rewrite, not file-size compression |
| Auto Rename | PDF.js text geometry heuristic | No text layer means original filename is kept; OCR is a separate explicit step |
| Stamp | Existing Watermark upgraded with text/image/page-range controls | Content rewrite can invalidate signatures; text font remains bounded by pdf-lib font support |
| Color Transform | PDF.js raster + deterministic pixel transform + pdf-lib rebuild | Entire output is intentionally rasterized; source text/vector/forms/annotations are not interactive |
| Secure manual redaction | Burn selected region, rasterize selected page, rebuild page tree | Selected page loses interactive/vector text; document-level catalog structures are not guaranteed in this security-first path |

## Existing equivalents — do not duplicate

The audit did not create separate tools where SolYan PDF already has an equivalent supported surface. Examples include merge, ordinary split/extract/reorder/remove/rotate, page numbers, metadata editing, protect/unlock, repair/compression, PDF-to-images, embedded-image extraction, image insertion through Editor/Stamp, crop/resize, N-up, booklet, forms, signing, PDF/A, compare, OCR and Office conversion.

A future parity pass should first verify whether a proposed feature is already covered by one of those surfaces before adding another dashboard card or engine path.

## Deliberately different from upstream behavior

- Auto Split uses the fixed SolYan marker `SOLYAN:PDF:AUTO-SPLIT:v1`, excludes divider sheets even when the divider is the first page, avoids empty output parts, and preserves the original bytes in the no-divider single-part path.
- Auto Split reuses the existing OCR/PDFium/OpenCV stack instead of adding ZXing/Java solely for QR detection.
- Color Transform explicitly identifies itself as rasterized because the reference behavior class rasterizes pages; SolYan does not call this lossless/vector color editing.
- Editor redaction no longer treats an opaque black rectangle as secure redaction. The security-first path excludes the original selected-page content stream from the resulting PDF.

## Dependencies and licensing decisions

- qpdf: Apache-2.0, separate backend CLI.
- pdf-lib: MIT, browser-side PDF operations.
- PDF.js/pdfjs-dist: Apache-2.0, browser viewer/rendering/text geometry.
- Tesseract: Apache-2.0, OCR/OSD binary in OCR service.
- pypdfium2/PDFium: existing OCR/render path with its recorded license notices.
- OpenCV 4.10: declared directly for QR detection rather than relying on PaddleOCR transitively.
- Poppler utilities: existing separate-process backend utilities; preserve distro/upstream licensing obligations.

No Java/PDFBox application runtime was added for this V1.2 parity pass.

## Deferred by product/provider decision

The following are intentionally **not** blockers for V1.2 self-contained completion because they require external product/provider/credential choices rather than more local PDF-engine parity work:

- multi-party / remote signature workflow;
- cloud-storage connectors;
- AI document summarization;
- PDF translation.

They must not be silently implemented or coupled to a provider until the corresponding product decision is made.

## Release rule

“Feature-complete” here means the self-contained parity implementation work is complete. A V1.2 release still requires the repository release gate from `AGENTS.md`: merge to current `main`, refresh current main CI, require relevant gates to pass, synchronize version/release metadata, publish the exact intended main commit, and re-fetch the resulting tag/release.
