# V1.6 PDF Translation — Hybrid Architecture

Date: 2026-10-16

## Product decision

SolYan PDF V1.6 uses a **Hybrid / local-first** translation architecture.

- A free path must remain available without a paid cloud API account.
- Local engines are preferred for privacy and zero per-document API cost.
- Cloud engines are optional quality/throughput providers.
- Cloud credentials are deployment/operator configuration and are never accepted from the SolYan browser UI.
- Translation/layout engines with incompatible copyleft licenses remain separate services; their source is not copied into the Apache-2.0 SolYan core.

## Layout engine boundary

The initial layout-preserving adapter targets the HTTP API exposed by:

- upstream: `PDFMathTranslate/PDFMathTranslate`
- upstream ref audited on 2026-10-16: `d16604dabb5c3f4c6d4daf37197b218b0dbd4df2`
- upstream release at that ref: 1.9.x / CLI reports 1.9.12 in the live diagnostic
- upstream license: AGPL-3.0

This upstream commit is a research/integration pin, not vendored source. SolYan communicates with the separately deployed service over HTTP.

The adapter contract used by SolYan is deliberately narrow:

1. `POST /v1/translate` with one PDF and a JSON `data` field;
2. `GET /v1/translate/{task_id}` until a terminal state;
3. `GET /v1/translate/{task_id}/mono` for translated-only PDF;
4. `GET /v1/translate/{task_id}/dual` for bilingual PDF;
5. `DELETE /v1/translate/{task_id}` as best-effort cleanup.

The SolYan core does not import, subclass, vendor, patch or redistribute the PDFMathTranslate Python package.

## Translation services

The V1.6 provider set is intentionally small and operator-configurable.

| Public service | Default class | Paid API account required | Notes |
| --- | --- | --- | --- |
| Argos | Local/free | No | V1.6 routes the public `argos` ID to the SolYan local Argos provider bridge through PDFMathTranslate's existing OpenAI-compatible provider interface. |
| Ollama | Local/free | No | Requires a local Ollama endpoint and configured local model. |
| OpenAI | Cloud | Usually yes | API billing is separate from a ChatGPT subscription; credentials live only in the external translation service. |
| DeepL | Cloud | Depends on account/quota | Credentials live only in the external translation service. |
| Google | Online | Upstream-dependent | Current 1.x adapter can be enabled without SolYan browser credentials; deployment/network policy still applies. |
| Bing | Online | Upstream-dependent | Current 1.x adapter can be enabled without SolYan browser credentials; deployment/network policy still applies. |

`TRANSLATION_ALLOWED_SERVICES` is the authoritative public allow-list exposed by a deployment. `TRANSLATION_LOCAL_SERVICES` is an operator classification, not a network-security guarantee. `TRANSLATION_UPSTREAM_SERVICE_MAP` maps a public SolYan service ID to an operator-side upstream provider ID without exposing that implementation detail in the browser.

The validated V1.6 free route is:

```text
browser service=argos
  -> SolYan backend public allow-list
  -> TRANSLATION_UPSTREAM_SERVICE_MAP=argos:openailiked
  -> PDFMathTranslate service=openailiked
  -> local OpenAI-compatible Argos bridge
  -> Argos EN->VI model
```

The response header remains `X-SolYan-Translation-Service: argos`; the browser never selects `openailiked` directly.

## Why Argos uses a provider bridge

The pinned PDFMathTranslate 1.x source contains a defect in its first-party `ArgosTranslator` path. Live diagnostics exposed two consecutive upstream errors:

1. the class imports `argotranslate.translate` although the real package is `argostranslate`;
2. after a runtime module alias bypasses that typo, the class still raises `name 'argostranslate' is not defined` and retries indefinitely.

SolYan therefore does **not** patch or fork the AGPL upstream merely to repair this path. Instead, the free lane uses PDFMathTranslate's existing `openailiked` provider interface and a small SolYan-owned local bridge in `engines/translation-provider/argos_openai_bridge.py`.

The bridge itself uses `argosopentech/argos-translate`, whose repository license is MIT. It accepts the PDFMathTranslate prompt locally, extracts only the source-text segment, translates with Argos and returns a non-streaming OpenAI-compatible chat-completion response. This keeps the upstream source byte-for-byte unmodified and makes the workaround replaceable if upstream later fixes Argos or exposes a better stable local-provider API.

## Free mode

The default SolYan service is `argos`.

The validated English -> Vietnamese lane pins:

- `argostranslate==1.11.0`
- model `translate-en_vi-1_9.argosmodel`
- model URL `https://data.argosopentech.com/argospm/v1/translate-en_vi-1_9.argosmodel`
- SHA-256 `86957101aa4099aa9a1a7492e41987d938d3cf0fdaf4fb684c0797a9d567dd16`

The model file is not committed to this repository. Operators download it into the external translation environment and verify the pinned hash before installation.

Ollama remains the second local option. It can improve translation quality depending on the selected model and hardware, but it is not required for the validated V1.6 EN -> VI free lane.

## External service setup

PDFMathTranslate's HTTP backend is deployed separately from SolYan. At the audited 1.x revision the HTTP backend uses Flask/Celery/Redis. The external AGPL service is intentionally not bundled into SolYan's default Docker Compose stack.

For the validated local Argos route:

1. deploy the pinned PDFMathTranslate HTTP backend separately;
2. install `engines/translation-provider/requirements.txt` in the local provider environment;
3. download and verify the pinned EN -> VI Argos model;
4. start `engines/translation-provider/argos_openai_bridge.py` on loopback, or on an explicitly trusted private service network;
5. configure PDFMathTranslate with the local OpenAI-compatible provider settings;
6. configure SolYan's public `argos` ID to map to upstream `openailiked`.

SolYan backend:

```text
TRANSLATION_SERVICE_URL=http://translation-service:11008
TRANSLATION_DEFAULT_SERVICE=argos
TRANSLATION_ALLOWED_SERVICES=argos,ollama,openai,deepl,google,bing
TRANSLATION_LOCAL_SERVICES=argos,ollama
TRANSLATION_UPSTREAM_SERVICE_MAP=argos:openailiked
```

External PDFMathTranslate process:

```text
OPENAILIKED_BASE_URL=http://127.0.0.1:18080/v1
OPENAILIKED_API_KEY=local-only
OPENAILIKED_MODEL=argos-en-vi
OPENAILIKED_STREAM=false
```

If PDFMathTranslate and the bridge run in separate containers, the bridge may bind to a private service interface only when `ARGOS_BRIDGE_ALLOW_NETWORK=1` is explicitly set. Do not publish that bridge port to an untrusted network.

## PDFMathTranslate 2.0 audit

The maintained `PDFMathTranslate/PDFMathTranslate-next` repository was also reviewed before locking this route. It is the newer BabelDOC-based 2.0 line and remains AGPL-3.0, but at the 2026-10-16 audit point its public README did not expose the stable 1.x HTTP task API used by SolYan and its Tier-1 translator list did not provide a first-class Argos path. Therefore V1.6 keeps the audited 1.x HTTP boundary for now instead of changing both layout engine and provider contract simultaneously.

This decision should be revisited when 2.0 exposes a stable service API suitable for the same provider-independent SolYan contract.

## Security and privacy boundaries

- Browser requests can choose only a public service identifier from the server-side allow-list; they cannot submit an arbitrary upstream URL or upstream provider ID.
- Public-to-upstream provider mapping is server-side configuration only.
- Browser requests do not contain provider API keys.
- The Argos bridge binds to loopback by default; non-loopback binding requires explicit opt-in.
- The Argos bridge request body is bounded and streaming is rejected.
- The upstream task identifier is syntax-bounded before it is reused in a path.
- PDF uploads are bounded by `TRANSLATION_MAX_FILE_SIZE` (100 MB by default).
- Source and target language identifiers are syntax-bounded.
- Translation polling is time-bounded.
- Arbitrary upstream error bodies are not reflected to the browser because provider exceptions can contain internal configuration or credentials.
- Local/free status is deployment metadata. Selecting a service marked local does not prove packet-level locality by itself.
- Selecting a cloud/online provider may send document text or document content outside the SolYan deployment. The UI displays this boundary.

## Output scope

V1.6 exposes two explicit outputs:

- **Translated PDF** — translated-only/mono layout result.
- **Bilingual PDF** — dual/bilingual layout result.

The adapter validates that a successful result is a PDF before returning it to the browser.

## Quality boundaries

V1.6 does not claim universal translation accuracy or pixel-identical layout preservation. Quality depends on:

- document structure and fonts;
- upstream layout analysis;
- selected translation service/model;
- available language pair/model;
- scanned/OCR quality when the source has no usable text layer.

The live EN -> VI gate proves that the pinned provider route can produce readable PDF outputs with translated Vietnamese text on a controlled selectable-text fixture. It is not a universal linguistic-quality benchmark.

Scanned document behavior remains dependent on the external layout/translation engine configuration. SolYan's existing OCR stack is not silently inserted into the translation path until a measured routing rule proves that doing so improves results.

## Verification strategy

The permanent lightweight SolYan CI gate remains provider-independent:

1. run a deterministic mock server implementing the audited PDFMathTranslate HTTP contract;
2. exercise translated-only and bilingual outputs through the real FastAPI route;
3. assert the submitted language/provider/thread payload, including `argos -> openailiked` server-side mapping;
4. assert local/cloud classification headers while keeping the public header as `argos`;
5. assert service allow-list, same-language rejection and non-PDF rejection;
6. assert that browser capabilities never invite API-key submission;
7. compile the local provider bridge and retain combined CI output as a durable artifact.
