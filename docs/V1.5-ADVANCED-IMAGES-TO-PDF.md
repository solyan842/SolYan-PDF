# V1.5 — Advanced Images → PDF

## Gap

The original SolYan Images → PDF tool created one PDF page per PNG/JPEG using the image dimensions as the page dimensions. Maintained Stirling-PDF also exposes page-fit behavior, A4 auto-rotation and color conversion.

## OSS-first decision

Keep the conversion browser-local and reuse the already-shipped `pdf-lib` plus the Canvas color-transform helper introduced for PDF → Images. No backend image converter, native codec or new npm dependency is added.

## Fit modes

### Image size

Preserves the original SolYan behavior and remains the default. The page dimensions follow the embedded image dimensions, with the existing 14,400-point maximum-side guard.

Upstream currently treats both `fitDocumentToImage` and `fitDocumentToPage` as image-sized page geometry, so SolYan intentionally collapses those duplicate geometries into this single user-facing option.

### A4 Fit

Creates an A4 page and scales the image proportionally to fit within it, centered on the page. No cropping or aspect-ratio distortion is introduced.

### A4 Fill

Creates an A4 page and stretches the image to the complete page bounds. This intentionally can change aspect ratio and is labeled as such in the UI.

For A4 modes, optional auto-rotate swaps the A4 page to landscape when the image is landscape.

## Color modes

- **Color**: directly embeds the original PNG/JPEG bytes through `pdf-lib`, avoiding needless raster re-encoding.
- **Greyscale**: decodes the image with `createImageBitmap`, draws to Canvas, applies luminance conversion and embeds a PNG result.
- **Black & White**: uses the same luminance conversion with a threshold of 128 and embeds the resulting PNG.

The shared luminance algorithm is the same helper used by advanced PDF → Images.

## Resource limits

- PNG/JPG/JPEG input only;
- maximum 200 images;
- maximum 50 MB per image;
- maximum 100 MB total input;
- Greyscale/B&W: maximum 25,000,000 decoded pixels per image;
- Greyscale/B&W: maximum 80,000,000 transformed pixels total.

Color mode does not force a Canvas decode/re-encode and therefore avoids the transform-pixel budget.

## Compatibility boundary

Browser-local `pdf-lib` natively embeds PNG/JPEG. Additional image codecs are not added solely for parity because that would expand runtime/dependency surface. EXIF-orientation normalization is not claimed in this lane; page auto-rotation is based on the dimensions exposed by the embedded image.
