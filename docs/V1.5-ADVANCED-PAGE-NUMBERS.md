# V1.5 — Advanced Page Numbers / Bates

## Gap

The original SolYan Page Numbers tool only painted a plain decimal number at bottom-center using a fixed font size and color. Maintained Stirling-PDF exposes a broader self-contained feature shape: selected pages, starting number, 3×3 position grid, margin presets, font size/type/color, custom text variables and zero-padding for Bates-style numbering.

## OSS-first decision

Keep SolYan browser-local and reuse the already-shipped `pdf-lib` engine. No backend route, new runtime, font package or network service is added.

## Accepted behavior

- selected page ranges continue to use the shared `parsePages()` syntax;
- starting number is preserved and increments in selected-page order;
- positions: top/middle/bottom × left/center/right;
- margin presets: 2%, 3.5%, 5%, 7.5% of the visible CropBox dimensions;
- font choices: Helvetica, Times Roman, Courier from the standard PDF fonts already available in `pdf-lib`;
- font size: 6–72 pt;
- color: `#RRGGBB`;
- template variables: `{n}`, `{total}`, `{filename}`;
- zero-padding: 0–12 digits, e.g. width 6 renders `1` as `000001`;
- default remains bottom-center so the prior product behavior is preserved;
- input is bounded to 100 MB.

## Geometry boundary

Placement is calculated against each page's CropBox, not a hard-coded A4/Letter canvas. This lane does not introduce a new page-rotation transform system: numbering follows the same PDF page-coordinate behavior as SolYan's existing browser-local stamp path. Rotation-specific visual remapping should only be added together with a dedicated geometry regression gate.

## Font boundary

`pdf-lib` StandardFonts use standard PDF/WinAnsi encoding. Before drawing each label, SolYan explicitly calls `font.encodeText(label)`. Labels containing unsupported characters fail with a clear message instead of silently producing incorrect glyphs. This especially matters when `{filename}` expands to a filename containing characters outside the selected standard font's encoding.

Adding an embedded Unicode font solely for this parity lane would expand package/font licensing and binary surface, so it is deferred until there is a broader typography requirement.

## Acceptance examples

- start `1`, zero-pad `6` → `000001`;
- template `Page {n} of {total}` on a 12-page file → `Page 1 of 12`;
- template `{filename}-{n}` strips the final file extension;
- selecting pages `1,3-5` increments labels in that selected order;
- position 8 remains bottom-center and is the default;
- a label wider than the CropBox is rejected instead of being knowingly painted outside the visible page;
- unsupported StandardFont characters are rejected explicitly.

## Verification

Frontend CI must compile and build the helper and page. No workflow file is changed in this lane because the connected GitHub session cannot modify `.github/workflows/*`; that restriction is not bypassed through alternate Git plumbing.
