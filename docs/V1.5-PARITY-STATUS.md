## Follow-on design decisions now locked

### Auto Redact

- Literal matching remains the default.
- Safe Regex is opt-in and deliberately rejects constructs that create high ReDoS risk or ambiguous zero-width behavior.
- Whole Word is a Literal-mode concern, not a regex-rewrite feature.
- Vietnamese/precomposed/decomposed literal text is NFC-normalized before matching.
- Security-first output still rasterizes only affected pages and never claims sub-run secure content removal while retaining the original affected-page content stream.

### Flatten

- **Forms + annotations** remains the qpdf path because it preserves selectable text/vector content where qpdf can flatten widget/annotation appearances.
- **Full Page** is explicitly destructive raster flattening and is opt-in.
- The two behaviors remain separate instead of using one vague “flatten” implementation.

### Page Numbers / Bates

- Default stays bottom-center for backward-compatible product behavior.
- Page placement is CropBox-relative.
- Standard PDF fonts are used without adding a Unicode font package solely for this lane; unsupported StandardFont labels fail clearly instead of emitting incorrect glyphs.
- Rotation-specific visual remapping is not claimed until it has a dedicated geometry regression gate.

### Metadata

- Normal edit mode modifies Document Information fields; it does not pretend to synchronize arbitrary XMP packets.
- Explicit Delete All clears Document Information and removes catalog `/Metadata` and `/PieceInfo`.
- Custom values support Unicode, while custom key names are intentionally restricted to a bounded safe PDF Name subset.

### PDF → Images

- PDF.js/Canvas remains the browser-local renderer.
- WebP is accepted only when Canvas actually returns `image/webp`; no fake extension fallback.
- TIFF is not added because browser Canvas has no native TIFF encoder and a new codec/runtime is not justified by current evidence.
- “Single image” means a vertical composite of the selected pages, matching the maintained OSS reference behavior.

### Images → PDF

- Existing image-sized page behavior remains the default.
- Maintained upstream currently gives `fitDocumentToImage` and `fitDocumentToPage` the same image-sized geometry, so SolYan exposes one non-duplicated “Image size” option instead of two identical controls.
- Color embeds source PNG/JPEG directly; Greyscale/B&W reuse the shared Canvas luminance transform.

## Audited surfaces intentionally kept as-is

These tools were inspected during the same V1.5 pass and no self-contained parity change with clear user value justified another implementation lane:

- **Watermark / Stamp** — already supports text/image stamps, page ranges, 9 standard positions plus custom X/Y, opacity, rotation, image sizing and deterministic page/file/date variables.
- **Bookmark / Outline editor** — already reads/writes outlines, supports nested hierarchy, reorder, indent/outdent, direct page destinations and outline removal.
- **Crop PDF** — already supports selected pages and four-edge page-box cropping with an explicit warning that crop is not secure redaction.
- **Resize / Scale pages** — already supports A0–A6, Letter, Legal, custom sizes, portrait/landscape and content scaling.
- **Color Transform** — already provides invert, grayscale, multiple high-contrast/two-color modes, DPI and bounded raster processing.
- **Compress Images** — existing qpdf `--optimize-images` plus Flate/object-stream recompression is honest about its engine capability; quality/resizing controls would require a different image pipeline rather than a fake qpdf option.

## Not silently pulled into V1.5

The following are major product families, not routine parity deltas. Per `AGENTS.md`, they require an explicit product decision before becoming implementation scope:

- cloud-storage connectors;
- remote or multi-party signing workflow / hosted key custody;
- AI summarization or other LLM document intelligence beyond the existing deterministic/OCR scope;
- PDF/document translation;
- other provider-backed features requiring new credentials, hosted services or materially different privacy boundaries.

## Current checkpoint conclusion

The audited self-contained V1.5 parity surfaces above are implemented or intentionally retained as-is. This checkpoint does **not** declare a release.

A V1.5 release can only be proposed after the `AGENTS.md` release gate is executed against current `main`: refresh repository-wide CI, verify all relevant release gates, confirm version/lockfile synchronization, confirm no temporary probe/debug workflow is present, and bind any tag/release to the exact intended `main` commit.

Until that release gate is complete, the correct repository status is **V1.5 active / implementation checkpoint complete for the audited self-contained lanes**.
