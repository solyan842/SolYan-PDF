# SolYan PDF V1.4 Close-out

Status: **SELF-CONTAINED SCOPE COMPLETE**

This record closes the V1.4 OSS-first self-contained parity pass after PR #108. It supplements `docs/V1.4-PARITY-AUDIT.md`, which contains the detailed architecture, security/fidelity boundaries and exact regression evidence for each accepted feature.

## Final accepted V1.4 capability

### PDF → PostScript / EPS

Status: **implemented and regression-gated**.

SolYan reuses the Poppler `pdftops` binary already shipped by the backend rather than introducing Ghostscript or another vector-conversion runtime.

Accepted behavior:

- `POST /pdf/to-postscript` exports multi-page PS or one-page EPS;
- PS keeps original source page sizes and supports an optional page range;
- EPS explicitly enforces one selected source page;
- PostScript Level 2 and Level 3 are supported, with Level 3 as the default;
- supplied user/owner passwords are tried consistently with other Poppler-backed converters;
- generated output is bounded to 250 MB and validated for PostScript/EPS headers before download;
- the frontend exposes the format/level controls and an explicit warning that PostScript is an executable page-description language that should only be interpreted by trusted/sandboxed software.

On the accepted PR #108 head `405852af999aba19c768c58cc95ebb737e72bbc0`, every pull-request-triggered workflow completed successfully before merge, including the dedicated PDF to PostScript CI, Backend CI, Frontend CI, Auto Redact Text CI, Color Transform CI and the remaining triggered regression suite. PR #108 merged into `main` as `824804b95b6491d15e3fe9580e0ee1fe1caed8b8`.

#### OSS-first decision

The maintained Stirling-PDF vector export path was reviewed. It uses Ghostscript devices for EPS, PS, PCL and XPS. SolYan intentionally implements only EPS/PS in this self-contained lane because the already-shipped Poppler runtime supports them directly. PCL/XPS remain a deliberate Ghostscript/GhostPDL dependency expansion rather than unfinished V1.4 work.

## V1.4 self-contained scope summary

The accepted V1.4 scope is intentionally small and high-value:

- **Auto Redact Text** — literal text-layer matching with security-first raster replacement only on affected pages, plus strict non-disclosure regression coverage;
- **Scanner Effect** — deterministic browser-local scan simulation with bounded DPI/noise/blur/yellowing/border/skew presets and an explicit rasterization/provenance boundary;
- **PDF → PostScript / EPS** — bounded Poppler vector export with multi-page PS, single-page EPS and PostScript Level 2/3 support.

These features reuse engines already present in SolYan PDF: PDF.js, Canvas, pdf-lib and Poppler. The accepted V1.4 scope adds no new application runtime or provider dependency.

## Deferred by design

The following are **not unfinished implementation work** for V1.4:

- PDF → EPUB/AZW3 — maintained implementations depend on Calibre;
- PDF → PCL/XPS — maintained vector export depends on Ghostscript/GhostPDL devices not currently shipped by SolYan;
- PDF → CBR — RAR creation adds deployment/licensing/tooling complexity while CBZ is already supported;
- inline PDF content-stream image removal (`BI … ID … EI`) — robust support needs a real content-stream parser/dependency expansion;
- multi-party/remote signing, cloud-storage connectors, AI summarization and PDF translation — provider/product/credential decisions remain required.

The current maintained-OSS audit found no additional self-contained gap important enough to justify delaying release merely to increase the tool count.

## Release readiness meaning

V1.4 can proceed to release packaging only after:

1. this close-out record and the final V1.4 parity audit are merged into current `main`;
2. current `main` CI is refreshed and all relevant release gates pass;
3. release version/package/lock/backend/changelog/manifest metadata is synchronized to the next patch version;
4. no temporary probe/preparation workflow remains in the release tree;
5. the release tag and GitHub Release are created against the exact intended `main` commit and re-fetched as non-draft/non-prerelease.

After this close-out, new feature work belongs to a later lane and must begin with a concrete user-value gap plus the repository OSS-first/speed gate rather than reopening V1.4 by default.
