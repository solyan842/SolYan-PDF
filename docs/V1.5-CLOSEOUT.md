# SolYan PDF V1.5 Close-out

Status: **SELF-CONTAINED SCOPE COMPLETE**

This record closes the audited V1.5 OSS-first self-contained parity pass after the V1.5 implementation checkpoint. It supplements `docs/V1.5-PARITY-AUDIT.md` and `docs/V1.5-PARITY-STATUS.md`, which contain the research record, engine choices, behavior boundaries and merge evidence for each accepted lane.

## Final accepted V1.5 scope

The accepted self-contained V1.5 scope is:

- **PDF → SVG** — Poppler-backed vector-first SVG export with bounded fallback behavior;
- **Certification signature / DocMDP** — optional certification signing on the existing local PKCS#12/pyHanko path with explicit DocMDP permission levels;
- **PDF Portfolio / Collection** — standard collection metadata plus embedded files using the existing qpdf attachment/JSON stack;
- **PDF Page Labels** — logical Arabic/Roman/alphabetic/prefix page labels through qpdf without drawing numbers into page content;
- **Safe Regex Auto Redact** — opt-in bounded regex matching with practical presets on top of the existing PDF.js matcher and security-first affected-page rebuild;
- **Unicode Whole Word Auto Redact** — NFC-normalized Unicode Letter/Number/Mark/underscore boundaries suitable for Vietnamese text;
- **Full Page Flatten** — explicit destructive raster flattening while retaining the existing qpdf forms/annotations flatten mode as a separate behavior;
- **Advanced Page Numbers / Bates** — configurable position, margins, templates, start number, zero-padding, font, size and color using the existing `pdf-lib` path;
- **Advanced Metadata** — broader Document Information editing, bounded custom fields and an explicit delete-all metadata path;
- **Advanced PDF → Images** — page ranges, real DPI, PNG/JPEG/WebP, color modes, annotation control and ZIP/single-image output using PDF.js/Canvas/JSZip;
- **Advanced Images → PDF** — image-sized or A4 Fit/Fill output, auto-rotate and color/greyscale/B&W processing using the existing browser stack.

The following audited surfaces were intentionally retained as-is because no self-contained parity delta justified another implementation lane: Watermark/Stamp, Bookmark/Outline editing, Crop PDF, Resize/Scale pages, Color Transform and Compress Images.

## Architecture / OSS-first conclusion

V1.5 reuses engines already present in SolYan PDF: qpdf, Poppler, pyHanko, PDF.js, Canvas, pdf-lib and JSZip. The accepted V1.5 scope does not add a new application runtime, hosted provider or credential dependency.

The PDF → Office V1 release policy remains unchanged at **27 cases / 68 source pages**. V1.5 does not weaken its target routing, editability, page-count, geometry or fidelity requirements.

## Security and fidelity boundaries

- Security-first Auto Redact rebuilds affected pages from raster output so matched source content is not retained; those affected pages lose their original interactive/vector structures.
- Literal matching remains the default. Safe Regex is opt-in and rejects constructs with unacceptable ReDoS/zero-width ambiguity risk. Whole Word remains a literal-mode feature and uses Unicode-aware boundaries plus NFC normalization.
- Full Page Flatten is explicitly destructive rasterization and remains distinct from qpdf forms/annotations flattening.
- Certification signing follows DocMDP permission semantics on the local PKCS#12 signing path. It does not introduce remote signing, hosted key custody or multi-party workflow.
- Page labels change logical document labels, not visible page-number artwork.
- Advanced metadata editing targets Document Information plus the documented delete-all path; it does not claim arbitrary XMP synchronization.
- PDF → Images and Images → PDF use browser rendering/encoding constraints. WebP is accepted only when the browser actually returns WebP; TIFF is not added without a justified codec/runtime expansion.

## Deferred by design

The following are **not unfinished V1.5 implementation work** and remain explicit product/provider decisions:

- cloud-storage connectors;
- remote or multi-party signing workflow / hosted key custody;
- AI summarization or provider-backed LLM document intelligence;
- PDF/document translation;
- other provider-backed features that introduce credentials, hosted services or materially different privacy boundaries.

## Release readiness meaning

V1.5 can proceed to release packaging only after:

1. this close-out record, V1.5 parity audit and status checkpoint are present in the release tree;
2. release version/package/lock/backend/changelog/manifest metadata is synchronized to the intended patch version;
3. the exact release branch/head passes all relevant CI and permanent release gates, including the unchanged PDF → Office V1 policy where triggered/relevant;
4. no temporary probe/diagnostic/preparation workflow remains in the release tree;
5. release preparation is merged into current `main` without unrelated feature work;
6. the release tag and GitHub Release are created against the exact intended `main` commit and re-fetched as non-draft/non-prerelease.

After this close-out, additional features belong to a later product lane and must start from a concrete user-value gap plus the repository OSS-first rule rather than reopening V1.5 by default.
